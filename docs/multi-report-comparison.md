# 在当前报告中查找其他报道

打开自己的一份报告，在简报下方选择“查找其他报道”。搜索词默认来自当前新闻标题，可以补充事件主体、地点或日期。确认当前模型的追问费率后，点击“查找并追加分析”。用户无需事先搜集多份报告，也无需从历史报告列表里猜选同一事件。

## 检索与比较

使用现有免费搜索链（自建 SearXNG → Bing → DuckDuckGo），没有付费搜索 API 回退。最多进行两轮检索、读取四个网页，选取最多三份不同正文供比较。URL 追踪参数、同文转载和原文副本会去重；不同域名不意味着来源独立。读取遵守现有公共地址、重定向、超时及体积限制，不执行网页脚本或绕过登录墙。

模型对照当前原文和实际读取的正文片段，判断是否属于同一事件。仅主题相近、发生时间或主体不一致、无法确认同一事件的材料不纳入。每个匹配需要能在两份正文中定位的事件锚点；摘要、相同主张和每条差异都需要同时引用当前原文与其他报道的逐字摘录。服务端核对所有引用，来源链接由实际读取结果生成。搜索摘要不能冒充已读正文，重复说法也不能当作事实核验。

结果展示新增信息、主张及报道侧重的差异、待补证据和可回查的引用。分析使用有长度上限的正文片段，不代表已经阅读全文；报道侧重不同不自动等于事实冲突。搜索有召回限制，无法保证每篇新闻都找到适合对照的报道。

## 保存与计费

采用当前模型的追问费率；自定义 API 的模型用量由服务商收取。搜索本身使用免费引擎。按钮提交的费率与服务端当前配置不一致时，先要求重新确认，不执行新的预扣。

任务在后台执行，可离开并重新打开报告查看。相同原文、版本、语言和搜索词复用已保存补充，不重复计费。改变搜索词会创建新的任务并确认费用。搜索无可读来源、没有同事件报道、模型失败、引用校验失败、原文在执行期间改变或任务超时，都释放对应预扣；重复点击与并发请求不重复扣点。

最新成功补充作为 `auditResultJson.relatedCoverage` 追加到当前报告，与报告一起备份。任务记录用于幂等、状态与费用管理；任务缓存清理或备份恢复后仍可从报告恢复补充。原有评分和正文保持原样，新检索失败时保留上次成功的补充。

补充默认仅报告本人可见，公共报告 DTO 会过滤这部分数据。修改、查询任务及读取缓存都重新校验报告所有权；不能用公开报告编号触发别人的检索任务。现有导出仍按原来的报告内容与费率工作。

## 旧入口兼容

首页常驻的大示例卡片已撤下；示例作为输入区旁的轻量帮助链接保留。主导航和“我的审视”不再引导用户手工挑选任意报告。旧 `/compare` 链接跳转到“我的审视”，从具体报告进入新流程。历史对比 API 及其已保存数据保留兼容，不再提供独立选择工作台。

本次复用已有报告 JSON、ServiceOperation 和点数账本，无需新增数据库迁移。
