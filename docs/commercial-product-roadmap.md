# 观隅产品改进计划

目标：帮助创作者和编辑完成发布前的证据核查与研究交付。商业方向是待验证假设，不代表已获得付费或留存验证。

## 本轮分批实施

每批单独分支与 PR；存在代码依赖时采用堆叠 PR 并明确合并顺序，不混入其他批次的 diff。沿用现有 CI，检查历史数据、归属权限、计费与页面交互。

1. **报告摘要与证据**：报告开头展示结论、缺口和核实事项；关键发现支持原文摘录和检索来源关联。摘录须匹配输入，链接须匹配提供的检索材料。模型判断与人工核验分别展示。旧报告不补造引用。
2. **首次体验与费用预告**：提供明确标注的示例，无需用户配置密钥；平台模型入口说明配置条件，个人 API 保留为高级选项。使用服务端同源的模型价格展示分析、追问与导出成本和失败处理规则。
3. **成本与订单状态**：记录外部搜索成本及成本覆盖范围，未配置费用不当作零。改善用户订单状态、到账信息与待处理订单的取消体验。保持服务端价格、权限和幂等性。
4. **多报道对比**：选择同一议题的既有报告，对照主张、证据、缺口与核验路径，保留原始报告链接；限制数量，检查归属与公开状态。先交付可复核的对照工作台，模型综合判断按现有计费路径单独生成。

## 后续阶段

5. **专题持续跟踪**：复用 RSS，只提醒新证据和重要变化；先验证重复需求，明确轮询频率与成本上限。
6. **团队审阅**：专题共享、批注、核实任务分配和版本确认；在个人专业用户的工作流得到验证后建设团队边界。

## 验证商业假设

用真实研究任务观察首次成功使用、来源核对、保存/导出、再次使用、实际支付和任务成本。不要以导出或浏览次数单独证明商业价值。套餐价格、自动支付服务和团队收费需结合实际运营配置与付费试验确定。
