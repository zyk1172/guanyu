# UI 审查与阅读工作台改版（2026-10-22）

当前没有线上访问、注册或首次分析的漏斗数据，无法据此认定“UI 太土”是使用量低的主要原因。本次通过本地运行、真实账号登录和桌面/手机截图，修复可以直接观察到的体验障碍。

## 观察与修改

| 观察到的问题 | 用户影响 | 本次修改 |
| --- | --- | --- |
| 默认黄褐底色、密集边框、11–12px 辅助文字；主次文字视觉接近 | 读起来费力，工具价值难以快速理解 | 清爽白色面板、深墨色文字、青绿色主操作；统一字号、间距和按钮尺寸。保留深色及儿童主题 |
| 首页同时展示链接、标题、来源、正文、关注点和完整费用说明 | 手机端需要滚过大量字段才能开始 | 正文优先，链接按需切换，可选字段折叠；任务价格直接显示，后续费率展开查看 |
| 示例夹在模型/API 说明中；手机上没有明确的体验入口 | 新访客难以在注册前看懂结果 | 突出免注册教学示例；手机介绍区直接提供示例入口 |
| 登录前填写的材料无法跨登录保留 | 用户需要重复粘贴和填写 | 每个标签页暂存最多 30 分钟；恢复后由用户确认并主动提交，不自动分析。存储受限时提示先复制材料 |
| 简报、结论与大量分析章节层级接近 | 报告很长，用户难以找到重点和核实路径 | 放大报告标题、简报及关键结论，增加吸顶阅读导航和证据展开；保留原文、评分、人工核验、追问和导出 |
| 卡片/输入框整体随指针缩放；新闻自动滚动 | 干扰阅读和输入，缺少用户控制 | 移除全局悬浮缩放、漂移光晕、新闻自动滚动；只保留轻量入场和状态动效，支持减少动态效果 |
| 分析步骤按固定时间自动“完成”，与服务端实际进度无关 | 容易误以为证据已完成核实 | 改为真实等待状态、经过时间和后台继续说明 |
| RSS 直接开始分析，与表单的费用确认分离 | 用户可能尚未检查材料就触发任务 | RSS 先将链接带入表单，由用户读取、检查并确认分析；请求超时后可重试 |
| 手机导航拥挤；设置面板过窄 | 操作难点、设置表格换行密集 | 可展开的移动导航及 Escape/焦点恢复；设置区域加宽；账号和记录页统一外观 |

## 实现范围

共享配色与文字样式、导航和页脚、首页输入工作台、示例和正式报告、分析等待状态、RSS、认证页面、账号设置、报告列表及收藏页面。默认主题存储值继续使用 `newspaper`，名称改为“清晰阅读”。新增界面文案覆盖现有七种语言。

没有改动数据库结构、模型调用协议、搜索提供商、费率和权限规则。测试使用隔离的本地数据库、普通/Pro/管理员账号及明确标记的虚构材料；模型回复来自本地模拟服务，不代表对真实新闻的分析质量验证。云环境对外 RSS 连接受限，因此同时检查了加载、不可用及重试状态；有内容时的筛选和手动滚动使用明确标记的虚构订阅验证。

## 验证与设计核对

- 完整 `npm run ci`：132 项自动测试，以及备份、普通用户权限、DeepSeek 设置等数据库检查通过；包含新增的草稿字段边界、过期和损坏数据测试。
- `npm run lint` 与生产构建；原有账号页和重新分析组件的两条导航规则警告保留。
- Playwright Chromium 实际走过密码登录、草稿恢复、任务创建与报告保存、证据导航、解析错误对话框、RSS 选择和手动滚动、移动菜单、三种主题和七种语言。
- 当前环境没有 Browser 插件，使用现有 Playwright/Chromium；界面检查覆盖 1440×1000、390×844，并补查窄屏和设计概念对应宽度。
- 用 `view_image` 对照设计概念与最终截图，检查了主标题/操作文案、两栏比例、字体层级、背景与主色、留白和面板边界、图标与真实品牌素材、报告结论和导航、手机布局及减少动态效果。
- 有意差异：使用真实教学示例与实际返回的 RSS/报告条目，未采用概念图中虚构的新闻列表；保留真实费用和余额提示；手机首页补充直接示例入口；报告保留全部业务功能及示例性质说明。

设计概念、前后截图与浏览器检查记录保存在本任务云环境 `/workspace/guanyu-local/redesign/`，不进入应用的静态资源或部署包。

## 上线后如何判断是否有效

建议观察访问 → 打开示例 → 注册成功 → 首次分析成功 → 7 天内再次使用。分别看手机/桌面、入口渠道及新老用户，避免把访问量不足、价值定位、登录成本、费用、响应速度或分析质量问题都归因于外观。后续优先根据真实流失环节做小规模验证，而不是继续堆加页面功能。
