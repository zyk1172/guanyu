# 新闻正文有效性校验

RSS 的“分析这篇”自动读取并校验正文，直接开始当前账号的分析任务。入口显示同一报价接口返回的分析费用；生成成功后按原规则计费。读取失败不提交任务、不用之前填写的正文代替；有效正文会显示在表单中。普通搜索结果和手动链接仍支持先读取、编辑再提交。

## 保存报告前的检查

1. 网页提取拒绝常见 HTTP 200 错误页、验证页、登录或订阅提示、仅有隐藏正文/JSON-LD 的页面，以及链接占主导的列表。原有公网地址、DNS 固定、逐跳重定向、响应大小和超时限制保留。不会登录、运行页面脚本或绕过付费墙。
2. 创建任务和直接分析 API 都校验正文的类型、长度、有效文字与明显的访问提示。纯标点和错误提示即使超过 50 字也不能提交；真实新闻中提及登录、订阅或网站错误并不自动判为无效。
3. 当前分析模型先返回内部 `inputAssessment`。有效正文为 `usable`，同时逐字引用输入正文中的一段实质性文字作为 `evidence`；未取得正文为 `unavailable`，非新闻为 `not_news`，与所选标题明显是不同事件为 `title_mismatch`。无效时模型只返回这个对象，停止打分。RSS 保留所选新闻标题供模型比对，联网线索不能补造缺失的原文。
4. 服务端在报告结构校验、保存和扣费前检查这个判断。缺失字段、未知状态、过短或不属于输入正文的引文都返回错误，不回填默认值。跨语言报告保留该内部对象原文，不翻译来源引文。历史报告的读取、下载不要求补齐此字段。

## 错误和费用

正文或页面无效返回 HTTP 422，带 `ARTICLE_BODY_MISSING`、`ARTICLE_ACCESS_BLOCKED`、`NOT_NEWS_ARTICLE` 或 `ARTICLE_TITLE_MISMATCH`。模型没有返回可验证的判断时返回 HTTP 502 / `ARTICLE_ASSESSMENT_FAILED`。错误结果不含报告或报告 ID，不保存报告、不扣分析点数；后台任务遇到正文无效直接失败，释放任务限额，不自动反复处理相同正文。

页面展示错误并提供重试或手动粘贴路径。分析点数仍只在报告与账本事务成功时扣除；自定义 API 提供商已发生的模型调用费用不由平台退回。一次点击可能需要读取及模型处理时间，不承诺所有新闻站点都可自动提取。

## 验证

`npm run test:article-input` 已纳入 CI。HTML 夹具覆盖正常中英文报道、错误/验证/登录/订阅页、隐藏和结构化单独正文、列表及合法报道中的相同关键词。真实本地 HTTP 模型和隔离数据库覆盖鉴权、CSRF、私网拒绝、拒绝结果不保存/不扣费、任务终止、正常直接/后台任务的单次计费及跨语言引文。

浏览器验证使用虚构 RSS/HTML 提取结果与本地模型，任务接口、持久化和账本使用真实本地服务。页面结构、访问策略和模型语义判断仍可能变化，测试夹具不能证明所有媒体的实时可用性或保证模型不会误判；无法确认时返回错误，用户可检查后手动提供正文。

不增加依赖、数据库迁移或部署环境变量。
