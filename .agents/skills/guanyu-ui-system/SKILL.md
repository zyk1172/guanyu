# 工作入口

先读仓库根目录 `DESIGN.md`，再读本次受影响页面、`components/ui/controls.tsx`、`components/ui/Dialog.tsx` 和 `app/ui-system.css`。如果这些文件不存在，先报告实际缺失，不自行补造另一套设计系统。

## 不可分裂的约定

- 用共享 Button、Input、Select、Textarea、Panel 和 Dialog。组件调用处只放布局，不覆盖几何、字号、边框、底色或焦点。
- 所有普通单行控件 44 px；按钮 14 px、输入 16 px、控件圆角 8 px、面板圆角 12 px。
- 配色使用语义变量，三套主题共用尺寸。状态有文字，危险动作不靠颜色单独传达。
- 带图标的控件使用现有 Lucide，图标按钮有名称与 44 px 点击区。
- 页头、字段、按钮、页脚、表格、弹窗逐一核对；不能只优化首页首屏。
- 不新增无功能徽章、渐变、光晕、装饰性数字、嵌套指标小卡片或批量入场动画。

## 流程

1. 明确这次要完成的用户任务；现有产品是操作界面还是阅读界面，以用户目标决定层级。
2. 修改前用当前页面截图和计算后的实际尺寸建立证据，保留内容、功能和已经确认的偏好。
3. 优先修复共享组件；同一问题出现在多个页面时不要逐页打 CSS 补丁。
4. 保留真实标签、原生输入/选择/链接、键盘焦点和语义；危险确认与敏感输入用 `useConfirmation()`。
5. 操作失败保留可恢复的输入；取消不提交；不得改变后台权限、原文公开设置或计费逻辑。
6. 检查默认、hover、focus-visible、按下、禁用、加载、错误、空状态和选中态。
7. 检查桌面、390/320 px 手机、三套主题、长中文/英文/URL；截图后查看图片，不能只读 DOM。
8. 涉及弹窗时验证焦点留在窗口、Escape、取消与关闭后焦点恢复；涉及敏感动作时验证取消没有发请求。
9. 完成 ESLint、构建与受影响业务检查。仓库的原生控件与浏览器弹窗限制必须通过。
10. 用简短结果和证据交付，把完整标准保留在 DESIGN.md；需要新变体先写清任务差异再实现。
